# 混合搜索功能 (Hybrid Search)

本项目实现了结合BM25关键词检索和向量检索的混合搜索功能，以提高检索相关性和准确性。

## 功能概述

混合搜索结合了两种不同的检索方式：

1. **向量检索 (Vector Search)**: 使用文本嵌入模型将文本转换为高维向量，通过计算查询与文档向量之间的相似度进行检索。
   - 优点：能够捕捉语义相似性，处理同义词和上下文关联性
   - 缺点：对关键词精确匹配的能力较弱

2. **BM25关键词检索**: 一种基于传统的词频统计的检索算法，特别适合精确关键词匹配。
   - 优点：在精确词汇匹配方面表现出色
   - 缺点：无法理解语义相似性

3. **混合检索 (Hybrid Search)**: 结合上述两种方法，获得两者的优势。

4. **地理编码增强**: 使用Google Maps API进行地点标准化和模糊匹配。
   - 优点：解决地点名称变体问题（如"香港"与"香港市"）
   - 优点：支持地点层级关系匹配（如查询"北京"可匹配"朝阳区"）

## 使用方法

### 通过API使用

发送POST请求到 `/api/chat` 端点，包含以下JSON格式的请求体：

```json
{
  "query": "你的查询内容"
}
```

响应格式：

```json
{
  "response": "AI回答内容..."
}
```

## 实现细节

### 依赖项

- LlamaIndex: 提供向量检索和BM25检索器
- rank-bm25: BM25算法的底层实现
- PyStemmer 和 NLTK: 用于文本处理和分词
- Google Gemini: 提供嵌入和LLM功能
- Google Maps API: 提供地理编码功能

### 核心组件

1. **混合检索器**:
   - `VectorIndexRetriever`: 基于向量相似度的检索
   - `BM25Retriever`: 基于关键词匹配的检索
   - `QueryFusionRetriever`: 融合上述两种检索结果

2. **元数据过滤**:
   - 支持基于标签、位置和日期的过滤
   - 使用`MetadataFilters`实现精确匹配和包含匹配

3. **地理编码功能**:
   - 使用Google Maps API进行地点标准化
   - 生成地点名称变体（如"北京"和"北京市"）
   - 提取地点层级关系（如"中国"、"北京"、"朝阳区"）
   - 缓存地理编码结果，避免重复API调用

### 实体提取

系统能够从自然语言查询中提取以下实体：

- **标签**: 使用 #标签 或 @标签 格式
- **位置**: 使用LLM和地理编码API智能提取和标准化
- **日期**: 支持各种日期格式，如"今天"、"7月1日"等

## 地理编码功能

### 配置

1. 在`.env`文件中添加Google Maps API密钥：
   ```
   GOOGLE_MAPS_API_KEY=your_api_key_here
   ```

2. 安装必要的依赖：
   ```
   pip install googlemaps geopy
   ```

### 功能特点

1. **地点标准化**:
   - 将用户输入的地点名称转换为标准形式
   - 例如："北京" → "北京市, 中国"

2. **地点变体生成**:
   - 自动生成地点的不同表达方式
   - 例如："北京" → ["北京", "北京市"]

3. **层级关系提取**:
   - 提取地点的行政区划层级
   - 例如："朝阳区" → ["中国", "北京市", "朝阳区"]

4. **缓存机制**:
   - 缓存地理编码结果，减少API调用
   - 缓存存储在`storage/geocode_cache.json`

5. **智能地点提取**:
   - 使用LLM从查询中提取地点名称
   - 回退到正则表达式方法作为备选

```bash
python test_geocoding.py
```

## 故障排除

### 流式响应处理问题修复

如果遇到以下错误:

```
AttributeError: 'Response' object has no attribute 'response_gen'
```

这是因为在非流式响应模式下，响应对象没有`response_gen`属性。修复方法是：

1. 对所有查询引擎设置`streaming=False`
2. 直接使用`response.response`获取响应文本，而不是尝试从`response.response_gen`中收集文本
